# ShareFund – שרת (Backend)

שרת לניהול קופה משותפת של קבוצה: הפקדות, משיכות, יתרות, חברים והודעות.
צד הלקוח (React) נכתב בנפרד ואינו חלק מהתיקייה הזאת.

| מה | כתובת |
| --- | --- |
| האתר באוויר (Render) | https://sharefund-client.onrender.com |
| השרת באוויר | https://sharefund-server.onrender.com/api |
| תיעוד ה-API (Swagger) | https://sharefund-server.onrender.com/api-docs |
| הקוד של השרת (GitHub) | https://github.com/BrachaBeker/sharefund-server |
| הקוד של האתר (GitHub) | https://github.com/BrachaBeker/sharefund-client |

משתמשי הדמו (מנהל: `123@gmail.com` / `123123`, ועוד) מופיעים בפרק [נתוני הדוגמה](#נתוני-הדוגמה).

> **מתחילים?** כדי להעלות את השרת לאינטרנט קראו את [START-HERE.md](START-HERE.md).
> כדי לכתוב את צד ה-React מול השרת קראו את [FRONTEND-API-GUIDE.md](FRONTEND-API-GUIDE.md).

## טכנולוגיות

| נושא | טכנולוגיה |
| --- | --- |
| סביבת ריצה | Node.js 20 ומעלה |
| שרת | Express 5 |
| שפה | TypeScript במצב strict |
| מסד נתונים | PostgreSQL |

| תיעוד | Swagger UI / OpenAPI 3 |
| בדיקות | Vitest + Supertest |

השרת לא משתמש בשום שירות בתשלום ובשום שירות AI.

## הרצה במחשב

צריך Node.js 20 ומעלה, ומסד PostgreSQL כלשהו. הכי פשוט להשתמש באותו מסד חינמי בענן
שמוסבר ב-[START-HERE.md](START-HERE.md) (חלק ב), כך שאין צורך להתקין PostgreSQL במחשב.

```bash
npm install
```

העתיקו את `.env.example` לקובץ חדש בשם `.env` ומלאו בו את `DATABASE_URL` ואת `JWT_SECRET`
(מחרוזת אקראית של 32 תווים לפחות). אחר כך:

```bash
npx prisma migrate deploy    # יוצר את הטבלאות במסד
npm run db:seed              # לא חובה: מוסיף את משתמשי הדמו והנתונים שלהם
npm run dev                  # מריץ את השרת עם טעינה מחדש בכל שינוי
```

השרת עולה בכתובת `http://localhost:5000`:

- בדיקת תקינות: `http://localhost:5000/api/health`
- Swagger: `http://localhost:5000/api-docs`

## משתני סביבה

| משתנה | חובה | הסבר |
| --- | --- | --- |
| `DATABASE_URL` | כן | כתובת החיבור ל-PostgreSQL |
| `JWT_SECRET` | כן | סוד לחתימת הטוקנים, 32 תווים לפחות |
| `JWT_EXPIRES_IN` | לא | תוקף הטוקן. ברירת מחדל `2h` |
| `PORT` | לא | ברירת מחדל 5000. ב-Render נקבע אוטומטית |

## מסד הנתונים

שש טבלאות. כל הסכומים נשמרים באגורות כמספר שלם.

| טבלה | תפקיד | שדות עיקריים |
| --- | --- | --- |
| `users` | משתמשים | `id`, `name`, `email` (ייחודי), `password_hash`, `must_change_password` |
| `groups` | קבוצות | `id`, `name`, `created_by` → users, `is_active`, `created_at`, `closed_at` |
| `group_memberships` | שיוך משתמש לקבוצה | `user_id` → users, `group_id` → groups, `role`, `balance`, `is_active` |
| `transactions` | הפקדות ומשיכות | `group_id`, `user_id`, `created_by`, `amount`, `type`, `is_shared`, `category`, `note`, `fund_balance_after` |
| `messages` | הודעות | `group_id`, `sender_id`, `content`, `to_all` |
| `message_recipients` | נמעני כל הודעה | `message_id` → messages, `user_id` → users, `read_at` |

קשרים: למשתמש יש הרבה שיוכים ולקבוצה יש הרבה שיוכים (רבים לרבים דרך `group_memberships`,
והצירוף משתמש+קבוצה ייחודי). לקבוצה יש הרבה תנועות והרבה הודעות. להודעה יש הרבה נמענים.

## הרשאות

- משתמש מזוהה תמיד לפי הטוקן, לעולם לא לפי מזהה שנשלח בגוף הבקשה.
- התפקיד (מנהל / חבר) שונה מקבוצה לקבוצה. לכן הוא לא נשמר בטוקן, והשרת קורא אותו מטבלת השיוך בכל בקשה.
- בלי טוקן תקין חוזר 401. עם טוקן אבל בלי הרשאה חוזר 403.
- משתמש עם סיסמה זמנית חסום מכל פעולה עד שהוא מחליף אותה.

| פעולה | מנהל | חבר |
| --- | --- | --- |
| הפקדה ומשיכה על שם עצמו | כן | כן |
| רישום מרוכז לחברים אחרים | כן | לא |
| רשימת חברים | שם, מייל, יתרה | שם ותפקיד בלבד |
| היסטוריה | כולל שמות | שמות רק בתנועות שלו |
| עריכת קטגוריה והערה של תנועה | כל תנועה | תנועות שלו |
| הוספה והסרה של חבר, איפוס סיסמה | כן | לא |
| שליחת הודעות | לנבחרים או לכולם | למנהל בלבד |
| יציאה מהקבוצה | לא | כן, ביתרה 0 |
| סגירת הקבוצה | כן | לא |

## נתוני הדוגמה

`npm run db:seed` יוצר ארבעה משתמשי דמו, שתי קבוצות, תנועות והודעות. הרצה חוזרת לא יוצרת כפילויות.
המשתמשים האלה קיימים גם בשרת שבאוויר, ובעמוד הכניסה של האתר יש כפתור כניסה מהירה לכל אחד מהם.

| שם | מייל | סיסמה | קבוצה 1: קופת ועד הכיתה | קבוצה 2: טיול משפחתי |
| --- | --- | --- | --- | --- |
| מנהל דמו | `123@gmail.com` | `123123` | מנהל | חבר |
| חבר דמו 1 | `111@gmail.com` | `111111` | חבר | מנהל |
| חבר דמו 2 | `222@gmail.com` | `222222` | חבר | – |
| חבר דמו 3 | `333@gmail.com` | `333333` | חבר | חבר (בחוב) |

קבוצה 2 במינוס (הוצא יותר ממה שהופקד), כדי להראות את מצב החוב בקופה.

## בדיקות

```bash
npm test
```

הבדיקות מוחקות את כל הנתונים לפני כל בדיקה, ולכן הן רצות רק על הכתובת שב-`TEST_DATABASE_URL`,
ומסרבות לרוץ אם היא לא מכילה את המילה `test`. הדרך הקלה: אותה כתובת כמו `DATABASE_URL`
עם `?schema=sharefund_test` בסוף. כך הבדיקות מקבלות טבלאות נפרדות משלהן.

הבדיקות מכסות: התחברות תקינה ושגויה, טוקן חסר / לא תקין / שפג תוקפו, הרשאות מנהל מול חבר,
יצירה / קריאה / עדכון / הסרה, בדיקות קלט, חיפוש וסינון, מניעת גישה למידע של אחרים,
חלוקת משיכה משותפת, תקינות ה-migrations ותקינות מסמך ה-Swagger.
